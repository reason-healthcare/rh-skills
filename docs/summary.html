The generated CQL library implements the CMS165 population logic. It handles both panel observations (LOINC 85354-9) and standalone component codes, extracts typed quantities from FHIR.Quantity, and evaluates the < 140/90 mmHg threshold:

/**
 * MeasureLibrary v1.0.0 — CMS165 Controlling High Blood Pressure
 * NQF 0018 | MIPS #236 | HEDIS CBP
 */
library MeasureLibrary version '1.0.0'
using FHIR version '4.0.1'

valueset "Essential Hypertension ICD10":
  '...ValueSet/vs-htn-dx-icd10'

valueset "Blood Pressure Observations LOINC":
  '...ValueSet/vs-bp-obs-loinc'

parameter "Measurement Period" Interval<DateTime>
  default Interval[@2024-01-01, @2024-12-31]

define "Initial Population":
  "Age 18 to 85"
    and exists "Qualifying Outpatient Encounters"
    and "Has Active Hypertension Diagnosed Before October"

define "Denominator Exclusion":
  "Has End Stage Renal Disease"  // ICD-10-CM N18.6

define "Numerator":
  "Denominator"
    and "Most Recent Systolic Value"  < 140
    and "Most Recent Diastolic Value" < 90

How the Tools Work Together

Two distinct systems drive the pipeline. The rh-skills CLI orchestrates the lifecycle — scaffolding, planning, reviewing, and packaging. ReasonHub MCP provides live terminology intelligence at the two points where coded clinical concepts must be resolved: concept enrichment during extraction, and code verification during formalization.

rh-skills CLI
  • Scaffold topic, download and normalize sources
  • Generate discovery, extract, and formalize plans
  • Present plans to human reviewer; record approve/reject decisions
  • Derive L2 structured YAML artifacts from normalized sources
  • Generate CQL source from L2 structured artifacts
  • Package FHIR IG bundle with dependencies
  • Maintain checksums and event log in tracking.yaml
ReasonHub MCP
  • Semantic search across SNOMED CT, LOINC, RxNorm, ICD-10-CM, UCUM
  • Verify individual codes are valid and active in live code systems
  • Retrieve UCUM units for quantitative LOINC observations
  • Check SNOMED subsumption relationships
  • Expand and validate FHIR ValueSet compositions
  • Return similarity-ranked results with display names
  • Surface discouraged codes (e.g., LOINC 55284-4)
rh CLI
  • Validate CQL syntax and semantics — rh cql validate <file.cql>
  • Compile CQL to ELM JSON — rh cql compile --output --debug --strict
  • Evaluate named expressions against FHIR Bundles — rh cql eval --data --trace
  • Parse tree and semantic analysis — rh cql explain parse/compile
  • Interactive CQL REPL — rh cql repl
  • Fetch FHIR packages for local validation — rh download package
